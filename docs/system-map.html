Every layer the system actually contains, from the Figma file where a value is decided to the person who installs it. Open a layer to see what is inside it. Where something does not exist, it is drawn as an empty band rather than left out.

<brand>-foundation

Four files. Palettes, radius primitives, font families and weights. 60–69 tokens each.

source

brand collection

130 semantic tokens per brand, each aliased into that brand's own foundation.

source

density collection

default and compact. 65 tokens each: the spacing scale, type ramp and line heights.

source

appearance collection

light and dark. 99 tokens each, across seven roots. Aliases into brand, so it composes without a cross-product.

The most common bug starts here. A brand mode duplicated from another brand keeps aliases pointing at the wrong foundation. The build treats that as fatal rather than letting it through.

Spacing and type, shared across all brands.

Foreground and contrast, emitted as a light block and a dark override.

brands.config.js

One entry adds a brand. Drives the build, Storybook and the snapshot modes.

This is the strongest part of the system. Better than most production design systems have. Nothing in the refactor discussion should put it at risk.

Eight sheets, 347–353 variables each. A light block plus a dark override, both matchable on any subtree.

App shell

TabBar, TabBarButton, Surface, Chip, Icon.

Every gate asks whether a component matches the design. None asks whether a page can be built from them. Component correctness does not compose, and this is where the system's identity actually lives.
