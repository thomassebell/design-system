# Updating from Figma

The most common workflow: a token changes in Figma, and the change needs to reach the deployed Storybook (and any consumer app). Here's how that goes end-to-end.

## The high-level loop

1. Edit the variable in the right Figma file
2. Re-export
3. Commit & push
4. CI builds; Vercel deploys; live Storybook updates within ~3 minutes

That's it. Nothing else needs touching unless the change implies new components or new token names.

## Step 1 — Edit in Figma

Where you make the edit depends on what's changing:

| What's changing | Edit in |
|---|---|
| A brand's colour ramp (e.g. Sebell's pine green, Brand B's grass green) | The matching foundation (`sebell-foundation`, `brand-a-foundation`, or `brand-b-foundation`) |
| A brand's font choices | The matching foundation |
| Universal sizes / typography sizes / line-heights | The main DS file |
| Compact-density spacing values | The main DS file (the `compact` mode of the relevant variable) |
| A component's colour / radius / per-state decision | The main DS file's `components.<name>.*` collection |
| A brand's semantic value (e.g. which palette feeds `color.warning.*`) | The main DS file's brand variable collection, under the relevant brand mode |
| Adding a new variable | Wherever it conceptually belongs (foundation if brand-specific primitive, DS file if semantic or universal) |

When in doubt: foundations are for brand identity; the DS file is for everything else. If you add a new semantic slot, **you must add it to every brand mode** — the build's cross-brand consistency check will fail otherwise (see "Step 4" below).

## Step 2 — Re-export

Use the same export tool you used last time. The eight files we consume live in `packages/tokens/figma-exports/` and follow the `.tokens.json` naming convention (Figma plugin's default):

```
sebell-foundation.tokens.json
sebell.tokens.json
brand-a-foundation.tokens.json
brand-a.tokens.json
brand-b-foundation.tokens.json
brand-b.tokens.json
default.tokens.json
compact.tokens.json
```

Replace the relevant files. **Naming must match exactly** — the build script reads them by name.

## Step 3 — Commit & push

```bash
cd "/Users/tseb/Documents/Sebell Design System/design-system"
git status
git add packages/tokens/figma-exports/
git commit -m "Update <what you changed>"
git push
```

## Step 4 — CI does the rest

GitHub Actions runs:

1. **`npm run tokens:build`** — runs `build.mjs`, which:
   - Reads all eight JSON files (3 foundations + 3 brand semantic + 2 density)
   - Runs the pre-flight cross-brand health checks:
     - **Alias misalignment** — every alias in `<brand>.tokens.json` must target `<brand>-foundation`, not another brand's foundation. Fatal.
     - **Structural parity** — every brand must define the same set of semantic keys. Mismatches fail or warn; Levenshtein-close names get flagged as likely typos.
     - **Type mismatches** across brands — fatal.
     - **Structural diff vs git HEAD** — informational; shows added/removed/renamed/retyped tokens and surfaces stale `var(--…)` references in component CSS.
   - Resolves cross-file aliases (`{primitive.size-16}` → `16`)
   - Converts colour objects to hex strings
   - Adds units to dimensional values (px, rem) based on path
   - Maps font-weight strings ("Semi Bold") to CSS numeric weights (600)
   - Adds font-family fallback chains
   - Emits six CSS files: `dist/{sebell,brand-a,brand-b}-{default,compact}.css`
   - Emits `dist/tokens.json` from the first combo (`sebell × default`) for `generate-swift.mjs` → iOS

2. **`npm run build`** — builds all packages and confirms components compile against the new tokens.

3. **`npm run lint`** and **`npm test`** — sanity checks.

4. **Storybook builds**, Vercel deploys; Chromatic captures visual snapshots for every story across every brand × density combination.

The whole pipeline takes ~2–3 minutes.

## Verifying after deploy

When Vercel goes green:

- Open the deployed Storybook → **Tokens** → the section you edited (Colors, Typography, Spacing, Radius).
- Use the toolbar to flip Brand / Density. The catalog re-reads CSS variables live.
- Open any component story that uses the changed token to make sure it still looks right.

## Common gotchas

| Symptom | Likely cause |
|---|---|
| Build deploys but the change isn't visible | Forgot to re-export from Figma after the edit. |
| Build fails: "cross-brand alias misalignment" | An alias in your brand's tokens still points at another brand's foundation. Typically happens when a brand mode was duplicated from another brand and aliases didn't get re-pointed. Fix in Figma and re-export. |
| Build fails: "$type mismatch across brands" | Same semantic token path has a different `$type` across brands (e.g. one is `color`, another `string`). Fix in Figma so they match. |
| Build warns: "likely typo" or "defined in only one brand" | A semantic key exists in some brands but not others. Either rename in Figma so the names match, or add the missing key to the brand that's lacking it. |
| Build fails: "no such variable / unresolved reference" | Renamed or deleted a variable that components still reference. The build's structural-diff section will list each `file:line` of the stale `var(--…)`. |
| One brand looks wrong, the others are fine | Edited in only one brand mode or foundation; the others still have the old value. |
| Density toggle has no visible effect on a component | The component's CSS is referencing a primitive (`--primitive-size-X`) instead of a semantic token (`--semantic-components-Y`). Primitives don't vary by density. |

## When you're adding new variables

You can add new variables in Figma freely — components don't break just because new variables exist. Only when you **reference** a new variable in component CSS does it become a runtime requirement. Add the variable, re-export, build runs fine, then update component code to use it when ready.

## When you're renaming or deleting

Coordinate with code:

- **Renaming a primitive**: build still works (semantic aliases still resolve, just to the renamed primitive).
- **Renaming a semantic token**: components referencing it will break. Update the component CSS in the same commit as the rename.
- **Deleting a token**: anything referencing it breaks. Use the same commit to either remove the references or repoint them.
