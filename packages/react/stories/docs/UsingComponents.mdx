# Using Components in Your App

For engineers consuming `@sebellds/react`.

## Install

```bash
npm install @sebellds/react
```

Public npm — no auth or registry configuration needed. `@sebellds/tokens` comes along as a dependency,
so a single install gives you both components and token stylesheets.

`react` and `react-dom` are peer dependencies (>=18). This is a **web** package: it renders DOM and
imports CSS, so it cannot be consumed by React Native.

## Import the stylesheets once

In your app's entry point, import **two** stylesheets – your brand's token
variables, then the component styles:

```ts
import "@sebellds/tokens/dist/sebell-default.css"; // token variables (pick your brand × density)
import "@sebellds/react/styles.css"; // reset + component styles
```

- The token stylesheet defines every `--color-…` / `--semantic-…` CSS variable.
  Components render unstyled without it.
- `@sebellds/react/styles.css` brings the baseline reset (`box-sizing: border-box`),
  shared utilities, and all component styles.

For a single-brand production app (the most common case), this is all you need – pick the brand CSS once at build time and you're done.

## Use components

```tsx
import {
  Button,
  Input,
  CheckboxField,
  Stack,
  Text,
} from "@sebellds/react";

export function SignupForm() {
  return (
    <Stack gap="medium">
      <Text variant="display4" as="h2">Sign up</Text>
      <Input label="Email" placeholder="you@example.com" />
      <Input label="Password" type="password" />
      <CheckboxField label="I agree to the terms" />
      <Button>Create account</Button>
    </Stack>
  );
}
```

The bare `Checkbox`, `Radio` and `Switch` are the controls on their own. The
`*Field` wrappers add the label, hint and error and wire up the accessibility –
that's what you usually want in a form.

## Components currently available

| Component | Key props |
|---|---|
| `Button` | `variant` (`solid` / `outline` / `danger` / `text`), `startIcon`, `endIcon`, `fullWidth`, `loading`, `disabled`, `as` |
| `IconButton` | `icon`, `label` (required – becomes the `aria-label`), `variant` (`solid` / `outline` / `danger`), `loading`, `disabled`, `as` |
| `Chip` | `variant` (`solid` / `outline`), `active` (announced via `aria-pressed`), `startIcon`, `endIcon` |
| `Input` | `label`, `hint`, `error`, `startIcon`, `endIcon`, `prefix`, `suffix` |
| `Checkbox` | `checked`, `indeterminate`, `onChange`, `disabled` |
| `CheckboxField` | `label`, `hint`, `error`, plus all `Checkbox` props |
| `CheckboxGroup` | `legend`, `description`, `error`, and the fields as children |
| `Radio` | `checked`, `value`, `name`, `onChange`, `disabled` |
| `RadioField` | `label`, `hint`, `error`, plus all `Radio` props |
| `RadioGroup` | `legend`, `description`, `name`, `options` (array of `RadioOption`), `value`, `onChange`, `error`, `disabled` |
| `Switch` | `checked`, `onChange`, `disabled` – a checkbox with `role="switch"` |
| `SwitchField` | `label`, `hint`, `error`, plus all `Switch` props |
| `TabBar` | Bottom-navigation chrome – a `<nav>` landmark. Takes `aria-label` and the tabs as children |
| `TabBarButton` | `icon`, `label` (both required), `active` (sets `aria-current="page"`) |
| `Text` | `variant` (`display1`–`display6`, `body`, `bodySmall`), `as` (sets the element – headings are always explicit), `weight`, `truncate`, `align`, `muted` |
| `Icon` | `size` (`sm` / `md` / `lg`), `label` (omit for decorative icons) |
| `Stack` | `direction`, `gap` (t-shirt sizes), `align`, `justify`, `wrap`, `as` |
| `Surface` | `surface` (`light` / `dark`) – scopes an appearance mode to its subtree. Sets the foreground tokens; the background is yours to paint |

Every prop is fully typed — hover any prop in your IDE for documentation.

## Switching brand or density at runtime

By default the app loads Sebell Default. To switch, replace the active stylesheet:

```html
<link rel="stylesheet" href="/path/to/brand-a-default.css">
```

The eight built CSS files live in `@sebellds/tokens/dist/`:

- `sebell-default.css`
- `sebell-compact.css`
- `prep-eat-default.css`
- `prep-eat-compact.css`
- `brand-a-default.css`
- `brand-a-compact.css`
- `brand-b-default.css`
- `brand-b-compact.css`

For a real product, you'll normally pick **one** of these at build time and never swap. Sebell and Prep+Eat are production brands; Brand A and Brand B are multi-brand pipeline test fixtures and aren't intended to ship in a real app. Multi-brand swapping is for engineers building products that intentionally render in different brands at runtime (white-label apps, etc.).

Your bundler can copy them as static assets. The active stylesheet is whichever one is currently in the DOM — swap it via JavaScript when the user toggles.

## App-specific overrides

Token CSS is set on `:root`. To scope an override (e.g. one section of your app uses a custom color), set the variable on a wrapper:

```css
.my-special-section {
  --color-surface-primary-main: #123456;
}
```

Anything inside that wrapper (Buttons, Inputs, etc.) picks up the override. CSS cascade does the work.

## Accessibility

All components ship with reasonable accessibility defaults — keyboard navigation, focus management, ARIA attributes. You don't need to add `aria-*` props yourself for standard usage. For unusual cases (e.g. icon-only buttons), check the component's Storybook story for the right props.

## TypeScript

Full type definitions are bundled. Strict mode friendly. Component prop interfaces are exported with the component:

```ts
import { Button, type ButtonProps, type ButtonVariant } from "@sebellds/react";
```

Use these for typed wrappers around components.
